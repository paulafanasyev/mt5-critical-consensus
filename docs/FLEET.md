# Парк MT5: сотни счетов у разных брокеров, логика в коде

Терминал MT5 — расходный материал. Код (`fleet/`) держит реестр счетов, сам разворачивает
изолированные portable-копии терминала под каждый счёт, проверяет авторизацию, торгует по
стратегиям, считает риск на счёт и на весь портфель и ведёт отдельный журнал.

## Почему так, а не «в терминале»

Два ограничения MetaTrader, которые определяют всю архитектуру:

1. **Один порт API на сессию Windows.** Терминал отдаёт данные Python-API через
   `127.0.0.1:22346`. Второй одновременно запущенный терминал получает
   `MCP bind error` и остаётся без API. Свой порт задать нельзя (проверено ключом `McpPort`
   в `common.ini` — игнорируется). Поэтому **каналом владеет ровно один терминал за раз**,
   и парк передаёт канал от счёта к счёту.
2. **Смена счёта внутри терминала рвёт канал.** `mt5.login()` переключает счёт, но IPC
   умирает до перезапуска терминала. Поэтому у каждого счёта **своя папка терминала** и
   свой автологин — счёт не переключается, а просто запускается нужный терминал.

## Слои

| Файл | Ответственность |
|---|---|
| `fleet/config.py` | реестр счетов, риск-профили, лимиты портфеля, разбор YAML без зависимостей |
| `fleet/terminals.py` | разворачивание portable-копии на счёт (жёсткие ссылки на бинарники), запуск, ожидание авторизации, остановка, передача канала |
| `fleet/broker.py` | поиск брокерского имени символа (`EURUSD` → `EURUSDm`), размер лота под шаг, режим исполнения, ретраи на реквотах, ATR/EMA |
| `fleet/risk.py` | дневной стоп счёта, лимиты позиций, расчёт объёма по риску, портфельные лимиты |
| `fleet/strategy.py` | сигналы: тренд H4+H1, пробой H1-диапазона; правила выхода (пик/откат, ATR-стоп) |
| `fleet/store.py` | sqlite (events, equity, trades, daystate) + JSONL-трейл для grep |
| `fleet/worker.py` | цикл по счетам шарда: подключиться → проверить счёт → вести позиции → открыть → отключиться |
| `fleet/shard.py` | процесс шарда (один на группу счетов) |
| `fleet/conductor.py` | держит шарды живыми, следит за книгой, включает паузу при портфельном стопе |
| `scripts/fleet.py` | CLI: `init`, `check`, `once`, `run`, `status`, `pause`, `resume` |

## Быстрый старт

```powershell
# 1. реестр
copy config\accounts.example.yaml config\accounts.yaml

# 2. разложить терминалы
python scripts\fleet.py init

# 3. проверить один счёт без торговли (символы, спред, сигналы)
$env:EXNESS_REAL_PASSWORD = "..."      # пароль не хранится в файле
python scripts\fleet.py check --account exness-real

# 4. один цикл в сухом режиме
python scripts\fleet.py once --account demo-metaquotes --dry-run

# 5. боевой запуск
python scripts\fleet.py run --interval 30

# 6. наблюдение
python scripts\fleet.py status
```

## Как добавить брокера и счёт

1. Установи **один раз** терминал этого брокера (обычным инсталлятором) и войди в счёт
   вручную с галочкой «Сохранить пароль». Скопируй путь к его папке данных.
2. В `config/accounts.yaml` добавь запись:

```yaml
  - name: broker-x-real-1
    login: 12345678
    server: BrokerX-Live
    mode: real
    enabled: true
    network: direct          # или vpn, если брокер блокируется в твоей сети
    shard: 1
    magic: 7100001
    terminal_source: C:\Program Files\BrokerX MT5   # откуда брать бинарники
    seed_config: C:\Users\...\MetaQuotes\Terminal\<hash>\config   # сохранённая сессия
    symbols: [EURUSD, GBPUSD, XAUUSD]
    risk:
      risk_per_trade_pct: 0.2
      daily_stop_pct: 0.5
      max_lots: 0.01
```

3. `python scripts\fleet.py check --account broker-x-real-1` — проверить, что терминал
   авторизуется и символы находятся.
4. Включить в `run`.

Счёт без сохранённой сессии можно завести через `password_env`: укажи имя переменной
окружения, и воркер передаст пароль в `mt5.initialize(...)`.

## Риск-модель

- **На счёт:** риск на сделку `risk_per_trade_pct`, дневной стоп `daily_stop_pct`,
  лимит позиций, абсолютный потолок лота `max_lots`.
- **На портфель:** суммарный дневной стоп, лимит позиций, лимит по золоту и по долларовым
  парам (чтобы сто счетов не стали одной гигантской позицией), пауза через файл `PAUSE`.
- **Выходы:** фиксация после отката от пика, жёсткий ATR-стоп, тейк по ATR.

## Масштабирование

Один процесс Windows = один терминал с API. Для сотен счетов:

- реестр общий, `shard` распределяет счета по машинам;
- на каждой машине свой `fleet.py run` со своим `--store` (или общий сетевой путь);
- для брокеров с блокировкой — `network: vpn`, туннель поднимается до запуска шарда.

Старт терминала на счёт ~3–6 секунд; полный обход 100 счетов ≈ 10 минут. Для минутного
реагирования счета делятся на шарды и машины.

## Диагностика

| Симптом | Причина |
|---|---|
| `MCP bind error on 127.0.0.1:22346` | запущено больше одного терминала; парк гасит лишние сам |
| `initialize: (-10005, 'IPC timeout')` | терминал не авторизован или занят другим; смотри `logs\*.log` счёта |
| `привязан чужой счёт` | в папке счёта сохранён другой логин; пересоздай `init --force` |
| символ не найден | брокер называет иначе; `check` покажет, что резолвится |
